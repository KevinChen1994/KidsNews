# 世界小报

从项目根目录工作。先读 [编辑规范](references/editorial.md)；需要参考节目分析时再读 `docs/参考节目分析.md`。默认面向约6–8岁儿童，晚饭后或睡前听；主题优先国内近期热点，国内没有合适事件再选国际新闻，兴趣只用于比喻和讲述入口。

个人称呼、年龄、兴趣和归档目标只读本机 `config/local.json`；缺省用 `config/local.example.json` 通用值。个性化稿件、成品和上传记录只放 Git 忽略的 `episodes/`、`samples/`、`delivery/`、`state/` 或 `private/`，不把个人信息写回 skill、公开文档和示例。公开模板可用 `scripts/prepare_script.py` 离线生成最终正文，再交给 TTS；不要改写已有音频对应的正文。

新稿以 `examples/episode-opening.txt` 的固定片头开场：短句口号、听众专属的节目身份，然后直接进入本期事件或具体问题。称呼按本机配置渲染；不加“晚上好”“早上好”“大家好”“欢迎来到”等问候。固定口号预计约8–12秒，以实测为准，不照搬参考主持人身份。用户指出已交付内容不符合要求时，在独立修正版同步正文、音频及当前归档入口，保留原缓存；不能只修改未来模板就宣称当前节目已修好。局部替换复用旧配音时，保存真实片段来源及调整后的时间轴，明确是本地拼接而非虚构整期供应商任务。

收尾使用 `examples/episode-ending.txt`：节目身份后直接说“我们下次再见”。不加“晚安”“早点休息”“做个好梦”等与睡眠或收听时段有关的祝福，晚饭后版与睡前版一致。配音前及归档回读同时检查片头和结束语；用户要求修正当前节目时，同步实际音频和逐字稿。

1. 读最近十四天的 `episodes/`（没有往期时明确记为首期），检查领域、地区、重复事件。读 `config/news-sources.json` 与 `docs/新闻信息源.md`：日常从 enabled 的 discovery 来源发现新闻；verification 来源按题核验。来源评审任务可试读尚待确认的 proposed 来源，不据此自行启用。名单全未启用时先完成来源评审或使用用户提供的资料，不宣称每日采集已运行。新增固定源应明确记录。
2. 先浏览国内综合新闻，优先当天及近72小时发生或有新进展的热点事件；必要时扩至近7天并说明理由。国内没有适合儿童、事实可靠且能讲清的事件时，再浏览国际新闻，并在brief.md记录国内候选不合适的具体原因。热点优先看近期广泛报道、受公众关注或有重要新进展的事件，记录关注度依据，不凭模型印象虚称热搜或编造排名。先过事实与儿童适宜性门槛，再在合适的国内候选中比较近期性、关注度与趣味。最近两周的领域和地区缺口只在这一优先顺序内兼顾，不为补国际比例跳过合适的国内题；不从动物、航天等兴趣关键词开始找全天选题。列出三至五个不同角度的候选、来源、事件及报道日期、热点依据、领域/地区、儿童切口与取舍理由，合并同一通讯社转载；候选不足时如实记录，不为凑数编造。更早材料明确标为近期回访或历史，不用新报道包装旧事件。区分事件发生日期、报道日期和核查时间，未来日期不能作已发生事实。没有可靠事实时保存缺口，不编当日新闻。Asia/Shanghai 是节目日期时区。
3. 每期一件主事件、一个核心理解、一个开放问题，默认约15分钟（通常14–16分钟，以实测为准）。先写出“谁遇到什么具体困难→做了什么→出现什么变化”，再选能被真实材料回答的好奇点；第一分钟交代事件，不用发布会流程或抽象术语代替事件。参考节目有整集杂志与头条问题链两层，借鉴时先区分；本项目沿用单主事件，用“具体矛盾→真实过程→递进追问→机制解释→换位看条件与代价→角色选择→回扣”展开，不机械添加其他新闻或虚构听众留言。解释服务事件，类比不接管故事；内容不足先补证据或换角度，不靠重复、放慢语速或长静默凑15分钟。输出到 `episodes/YYYY-MM-DD/`：`brief.md` 保存来源、逐条事实依据、选题理由、类比边界、未知之处、问题链与各段新增内容；`script.txt` 只含可朗读正文；`production.md` 保存音乐位置和停顿。同日另选新题或重制，使用该日目录内独立子目录并沿用当日声线，不覆盖已有正文、成品和缓存，归档按日期与题目/版本查重。
4. 自审：每条核心事实对应可读取的正文证据，标题、摘要和搜索快照只作线索；优先追到原始公告、论文、赛事记录，关键争议再找独立报道，不把同稿转载当多源验证。按编辑规范做“事件是否清楚、好奇点是否兑现、真实细节是否支撑、解释是否回到事件”的检查；若没有具体案例或可观察变化，补证据、删减无用支线或换角度，不拿假设故事补齐新闻。删掉无法服务主问题的百科支线、重复结论和反复的边界声明；需要的限定紧贴对应事实说一次。检查类比是否改变事实、开放问题是否接着事件且有多种合理答案、少量互动是否真留思考空间。不虚构引语/现场/情绪；区分事实、观点、预测、想象；无考试口吻、恐吓悬念、商业诱导。睡前版平静收束。
   已有“生词多、跟不上经过”的实际反馈，额外执行编辑规范的“听懂优先”检查：以一个主要对象的动作串起经过，成人分析词改日常话，必要新词当场解释；不叠加多个条件的安排题。选题比较时检查孩子能否立刻对一个真实细节好奇，不能只凭题材标签认定有趣。易懂修订仍保持约15分钟（通常14–16分钟），不得把降低难度当作缩短时长的授权，不得自行添加短版例外；只有用户明确改时长才调整。
5. 用户要求音频时，读 `docs/音频制作.md`，直接调用 `scripts/audio.py tts`，不另用配音 skill。脚本按节目日期从Vivi/云舟随机选一种并保存，整期及同日重跑沿用。复用 `assets/music/` 库存，读取 `config/music-library.json` 与 `assets/music/catalog.json`，片头固定 `01-opening`，主底乐优先避开最近3期，每期 production.md 保存曲目ID、位置、留白和选曲原因。音乐库不合适时留白或报告缺口；生成音乐属于一次性维护，只有用户日后明确授权扩充才可调用。首次制作或调整声线/参数时可用短样做技术验证，已有成功的同参数样本可复用，不每天重复付费试听，也不等待人工批准。
6. 用 `scripts/mix_audio.py` 可制作简单底乐试听，整期用 `scripts/assemble_episode.py` 按 `production.md` 和时间轴编排；不能把整条底乐循环当作精细成品。配音前检查正文起首与按配置渲染的固定片头一致；交付时再核对音频来源文本、当地最终正文及当前归档页的逐字稿起首，不以模板已改代替交付检查。保留事实核查、音频与正文对应、完整解码、时长、响度及停顿检查，完成后直接标记“已通过”并归档交付，不设人工审核或听审门槛，不虚构已试听。Notion逐字稿仅保存在页面正文，不再写同名字段，使用“状态”字段并设“已通过”。保存 `report.md` 说明完成/失败与技术检查结果；用户后续反馈再按需修改。

重复运行先复用同日事实底稿和已经成功的音频。失败留下已完成结果与原因，不能拿旧成品冒充当日新闻。此 skill 不自行创建定时任务或向他人推送；这些由用户另行指定。
