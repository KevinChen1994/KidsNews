# 音频制作操作说明

配音是写好稿后的脚本步骤，不单独注册 skill。每日创作由 `kids-news-editor` 负责，以下只处理已定稿的文字、声音与库存音乐。

## 火山配音

在项目根目录运行 `python3 scripts/audio.py tts --help`。脚本从项目 `.env` 读取凭据，不要读取或展示值，不用 shell source 密钥文件。

支持新版 `VOLCENGINE_API_KEY`；否则使用 `VOLCENGINE_APP_ID` 和 `VOLCENGINE_ACCESS_TOKEN`，兼容当前已有拼写 `VOLCENGINE_ACCECC_TOKEN`（小写旧名同样可用）。`VOLCENGINE_SECRET_KEY` 不用于此接口，不能把它当作 Access Token。系统环境变量优先于 `.env`。

`config/voice-options.json` 列有6个官方候选，Vivi、小何、云舟、小天四种已实际调用成功（两女两男），其中Vivi与云舟已由用户选定为日常声线，小何和小天不参与日常选择；这不是供应商总音色数。当前状态见 `docs/声线选择.md`。

个人称呼与听众资料仅保存在 Git 忽略的 `config/local.json`，缺省使用 `config/local.example.json` 通用值。先把最终朗读正文保存为 UTF-8 文本，去掉来源、标题层级和舞台指示。日常不传 `--speaker`，脚本按 `config/voice-options.json` 在Vivi和云舟中等概率随机选一种，保存于 `state/voices/YYYY-MM-DD.json`。同一天重跑复用，允许连续多天同声线（随机不是轮流交替）。补做旧日期须传 `--episode-date YYYY-MM-DD`，同一期全部正文沿用这次选定的声线。语速默认 -8，用户明确要求其他声线试听时才用 `--speaker` 覆盖。

```bash
python3 scripts/prepare_script.py --template examples/voice-preview.txt --output samples/public-demo.txt
python3 scripts/audio.py tts --text-file samples/public-demo.txt --output samples/public-demo.mp3 --speaker zh_female_vv_uranus_bigtts
python3 scripts/audio.py tts --text-file episodes/2026-11-05/script.txt --output episodes/2026-11-05/voice.mp3 --episode-date 2026-11-05 --speech-rate -8
```

模板准备脚本会将配置中的称呼和节目名写成最终正文，拒绝覆盖已有稿件；TTS 拒绝未渲染的占位符。归档使用同一份最终正文，不在配音后修改对应稿件。试听、正文、成品、上传状态与缓存仅保存在 Git 忽略的本机目录。

同日换题或重制时，在 `episodes/YYYY-MM-DD/` 下新建独立子目录，正文、人声、混音计划、成品与归档缓存均放入该目录；TTS仍传同一 `--episode-date`，复用当天声线。交付用不同标题文件名，Notion按日期与题目/版本查重，不覆盖此前节目。

用户要求修正当前交付时，应更新原节目归档入口的逐字稿和音频，并回读核对，原版缓存保留。只替换片头或结束语时，仅生成对应短段，按字级时间戳在相邻完整句子之间的空隙裁切，复用其余已验证音频。拼接侧车明确标为 `local-composite`，保存各段来源文件、摘要、切点及平移后的时间戳；来源若已经是拼接版，保留能追溯到原TTS的完整侧车链，不能伪造成一次整期供应商请求。PCM中间文件可用 `voice.wav` 交给编排脚本。最终仍须做整期正文一致性、完整解码、响度及停顿检查。替换当前Notion正文时优先定点更新，同步正文音频、音频字段、时长及章节时间；原生音频块定点匹配失败时，读取完整当前正文，在保留其他内容及原生引用的前提下仅换音频源后写回。网盘修正版使用清楚的新文件名，保留旧版。

`--dry-run` 查看请求，不提交，需显式传 `--speaker` 避免写入每日选择状态。正式请求使用 `seed-tts-2.0`、24kHz MP3，开启字级时间戳；`--speaker` 可覆盖声线。只对已有文字配音，不自行补写新闻。

输出同名 `.json` 保存请求指纹、任务ID、状态、时间戳与文件摘要，不保存密钥或临时下载链接。完成后用 ffprobe 核对时长并试听开头、专有名词、数字和结尾，HTTP成功只表示接口完成；通过后续技术检查后直接放行，不等待人工听审。

超时重跑同一命令只查询原任务，不再次提交。输出路径被不同请求占用时另选路径。提交结果不确定、鉴权失败、余额或权限不足时停下并报告，不能自动切模型或循环付费重试。下载链接失效可重新查询任务；任务服务端保留七天。锁文件存在时先核实原进程是否还活着。

官方协议：[提交](https://docs.volcengine.com/docs/doubao-voice/task-sub-mission?lang=zh)、[查询](https://docs.volcengine.com/docs/doubao-voice/result-query?lang=zh)、[旧版鉴权](https://docs.volcengine.com/docs/doubao-voice/old-version-console-authentication-reference-example?lang=zh)。接口变更或新增选项时先核对这些文档。

## 库存音乐与混音

读 `config/music-library.json`、`assets/music/catalog.json` 和 [音乐库](../assets/music/library.md)。片头固定 `01-opening`，主底乐优先避开最近3期；在每期 `production.md` 记下曲目ID、用途、起止位置、留白与选择理由。讲新概念、区分事实、等待回答时允许完全留白。只用技术验证通过的曲目；历史人工试听记录照实保留，不作为节目交付门槛。

`scripts/mix_audio.py` 用于简单低音量底乐试听；整期的转场和互动停顿仍须按 `production.md` 编排。交付前核对总时长、开头和结尾、专有名词，并在 `report.md` 记录技术检查结果。生成完成并通过检查后直接标记“已通过”，不设人工审核；不声称已经人工试听。

整期可用 `scripts/assemble_episode.py --plan episodes/YYYY-MM-DD/mix-plan.json --output episodes/YYYY-MM-DD/final.mp3`：以TTS字级时间戳定位正文，插入指定长度的思考留白，在明确位置铺库存音乐，不自动循环曲目，不覆盖既有输出；同名 `.mix.json` 保存实际时间轴与摘要。通用计划示例见 `examples/mix-plan.json`；将其中日期替换为实际节目日期，文字锚点须与最终正文完全匹配。当前脚本使用 `technical_validation: decoded-successfully` 曲目，不要求人工审批。

历史试跑已验证整期生成与单次归档。上传前检查目标工作区的当前单文件上限，高码率母版超限时保留本地，交付版从原始人声与音乐重新混为64kbps单声道MP3；不要重新调用TTS。计划可设 `output_bitrate` 与 `output_channels`。上传前核查实际大小及响度，不假定十分钟文件必定小于上限。网盘与Notion使用同一份交付版以保持一致。

当前节目默认约15分钟。若目标仍受5MiB单文件限制，15分钟64kbps或48kbps可能超限，可在保留本地母版后，从原人声与库存音乐另混40kbps单声道交付版（编排脚本已支持），并实测大小、完整解码、响度与峰值。不能为文件上限缩短正文、拉快语速或重跑付费TTS；网盘与Notion使用同一交付版。

MP3编码后真峰值可能高于混音滤镜目标，低码率版尤其要实测。计划可用 `output_true_peak_db` 在-9至-1dBTP间预留余量，默认仍为-1.5；40kbps长版可先用-3.5，再检查最终响度与真峰值。检查失败只调整本地混音，不重跑TTS。

Notion完整逐字稿只写页面正文，不再创建或写入“逐字稿”字段；“状态”设为“已通过”。

音乐只生成一次，现有库长期复用，策略保持 `reuse-only`。库存不合适就留白或报告缺口。历史接口、计划和失败处理保存在 [音乐生成记录](音乐生成记录.md)，只有用户日后明确要求扩充时才读取执行；未完成的历史计划不能自动恢复。
